# ADR-029: ADC 驱动

## 状态

Partially Done：
- `/dev/adc0`（ADC1）内部通道单次查询（VREFINT 通道 17）— **真机 MEASURED**
  （drivertest_adc PASS，零回归已在真机门禁证明）。
- `/dev/adc1`（ADC2）多通道扫描 + GPDMA 搬运 + 模拟看门狗（AWD1）
  （VBAT 通道 16 + VDDCORE 通道 17）— 代码完成并编译通过，但 **DMA 搬运
  在 DEV-boot 真机上被 RISAF 防火墙阻断**（GPDMA1 的 CID 未被授予任何
  SRAM 区域写权限，写入被静默丢弃、读回全 0，CSR 报 TCF 却无数据）。
  根因已完整定位（见下「真机 DMA 阻断根因」）。**更正（2026-07-31，决定性）**：
  曾判「修复 = 编程 RISAF 区域授予 GPDMA1 的 CID」并推迟留待返回。经
  `dma2d_unlock` 真机实测证伪该思路对 DEV-boot NuttX 可行——对能经 RIMC 设
  CID 的 DMA2D，即使 region+CID override 全部回读生效，写 SRAM 仍被拦（门在
  主设备总线身份，非 region 白名单）；GPDMA1 更连 RIF master index 都没有、
  CID 无法经 RIMC 重设，故 NuttX 侧更无从解锁。**ADC-DMA 在 DEV boot 保持
  PARTIAL，无 NuttX 解法**（轮询单次采样已 MEASURED）；FSBL/secure-world 能否
  解属未测。详见 ADR-039「决定性更正」节与
  [[hw-stm32n6-risaf-dma2d-grantable-gpdma-not]]。

### 真机 DMA 阻断根因（MEASURED，2026-07-28）

在 DEV boot（固件由 GDB 加载到 SRAM）下 GPDMA1 无法把数据写入任何
SRAM，尽管通道寄存器编程与时序完全正确、CSR 报完成（TCF 置位、无
错误位）：

- GPDMA mem2mem 复制常量（两端都在普通固件 SRAM）：写回 **0**，
  CSR=0x301（TCF，无错误）。
- 同样复制完全落在 **AHBSRAM1**（0x38000000，RM 明示的 "DMA 首选"
  区，MEMENR=0x17ff 已使能）：仍写回 **0**；同地址 CPU 写入成功
  （SWD 实读到 0xdeadbeef）。
- 把通道置**安全**（GPDMA_SECCFGR.SEC0=1 + CTR1.SSEC|DSEC）：**仍为
  0**。安全属性不是判别因素。
- GPDMA 外设→内存（ADC DR→SRAM）：0，且置 **DTEF**（CSR bit10）。
- RISAF21（"AHB RAM 0"，0x54035000）：CR=0（**GLOCK 未置，仍可重配**），
  区域 0 CFGR=0（**BREN=0，区域未启用**），IAESR=0。

结论：AXI SRAM 防火墙（RISAF）未授予 GPDMA1 的 compartment ID(CID)
写权限，写入按 "illegal writes ignored / reads return 0" 静默丢弃。
非驱动/缓存/安全位问题。

> **修复方向更正（2026-07-31，决定性）**：早先设想「编程 RISAF 区域
> （BREN + STARTR/ENDR 覆盖缓冲 + CIDCFGR 授予 GPDMA CID）即可修复」。
> `dma2d_unlock` 真机实测证伪此路对 DEV-boot NuttX 可行——见状态节更正。
> 门在主设备总线身份，region 白名单授权解不了；且 GPDMA1 CID 无法经 RIMC
> 重设。DEV boot 下无 NuttX 解法。

> 注：Renode 不模拟时钟门控与 RIF，此阻断在仿真中不可见 —— 以真机为准。

## 上下文

STM32N647X0 有 ADC1/ADC2，特性：
- 12-bit SAR ADC，最高 16.5Msps
- 多路复用输入通道
- 支持 DMA 传输
- 注入通道（高优先级）+ 规则通道
- 模拟看门狗（阈值检测）

DS14791 Section 23: ADC。
ADC 是连接模拟世界和数字世界的桥梁。

## 决策

同一份驱动注册两个 ADC 字符设备，覆盖单次查询与扫描/DMA/看门狗两条路径：

### /dev/adc0（ADC1）— 单次查询（保持不变）

软件触发 + 轮询下半层，采集芯片内部电压参考 VREFINT（通道 17）。选择
内部通道是因为它无需外部布线，可在任意板子上直接跑真机 drivertest。
**此设备行为刻意保持不变**，使 drivertest_adc 继续 PASS。

### /dev/adc1（ADC2）— 多通道扫描 + DMA + 模拟看门狗

补齐原先延后的三个子项。选片内通道 VBAT（通道 16）+ VDDCORE（通道 17）
组成 2 元素规则扫描序列——两者都是无需外部布线的片内电压，且分居 ADC2
的不同内部路由，可在同一实例扫描：

- **多通道扫描**：SQR1 L=1，SQ1=VBAT / SQ2=VDDCORE；VBAT 经 CCR.VBATEN
  路由，VDDCORE 经选项寄存器 OR.OP2 路由（不走 CCR 路径位）。
- **DMA 搬运**：CFGR1.DMNGT=01（DMA one-shot），每次软件触发一遍扫描，
  结果经 GPDMA 外设→内存搬到 32B 对齐缓冲区（DCACHE 已开，ADR-007，读回
  前 invalidate）。DMA 走**共享 GPDMA 驱动新增的 p2m 函数**
  `stm32n6_dma_start_p2m()`，不改动既有 `stm32n6_dma_start`（详见 ADR-011）。
- **模拟看门狗（AWD1）**：CFGR1.AWD1EN 监视整个规则组，阈值 LTR1/HTR1
  默认全开（不触发），经 `ANIOC_WDOG_UPPER`/`ANIOC_WDOG_LOWER` 收窄；
  越窗置 ISR.AWD1，每遍扫描检查并清除。

`/dev/adc1` 由新 Kconfig 符号 `STM32_ADC2`（depends on STM32_ADC1，
select STM32_GPDMA）门控，ADC2/DMA/AWD 相关代码全部 `#ifdef` 包裹——
关闭时 ADC1-only 构建不引入任何 GPDMA 依赖。

### 修正的共享 GPDMA 头 BUG

写 p2m 时发现既有 `stm32n6_dma.c` 的 `GPDMA_CTR2_DREQ (1<<0)` 与
`GPDMA_CTR2_DREQ_MASK (0x7f<<4)` 与 CMSIS 矛盾。按 CMSIS 正确布局为
REQSEL[7:0]、SWREQ bit9、DREQ bit10；TCEM 也应是 [31:30] 而非 [15:14]。
已改正（既有 mem2mem 路径只用 SWREQ，未受错误位影响，故无回归）。

### STM32N6 与 STM32H7 的关键差异

移植 stm32h7 参考实现时踩到三处芯片差异，均已在真机验证中定位：

1. **无 ADVREGEN 位** — N6 清除 CR.DEEPPWD 即使能 ADC 电压调节器
   （需 ~10µs 稳定），不存在 H7 的独立 ADVREGEN 位。
2. **无盲校准** — H7 的 "ADEN=0 时置 ADCAL 等待自清零" 流程在 N6 上
   永不清零（N6 用 ADC 使能后的平均偏移测量校准）。校准仅修正静态
   偏移，对读 VREFINT 无意义，故完全跳过。
3. **VDDA 模拟供电开关** — 必须置 PWR.SVMCR3.ASV（bit 12，等价于
   HAL_PWREx_EnableVddA），否则转换照常完成、EOC 照常置位，但数据
   寄存器恒读回 0。此位缺失是真机 raw=0 的根因（经 ST ALIENTEK N647
   BSP adc.c 交叉验证确认）。

此外 N6 上电后可能过早清除 ADEN，故 ADEN 置位后需轮询 ADRDY 期间
反复重写 ADEN 直至就绪。

## 设计

### 模块架构

```
ADC1/ADC2
├── 转换模式
│   ├── 单次转换 (Single)
│   ├── 连续转换 (Continuous)
│   ├── 扫描模式 (Scan, 多通道)
│   └── 注入模式 (Injected, 高优先级)
│
├── 通道配置
│   ├── 规则通道 (Regular, CH0-CH19)
│   ├── 注入通道 (Injected)
│   ├── 采样时间可编程
│   └── 模拟看门狗 (阈值比较)
│
└── 触发源
    ├── 软件触发
    ├── 定时器触发 (TIM1/TIM8 TRGO)
    └── 外部中断触发
```

### NuttX 框架对接

```
NuttX ADC 框架:
  adc_register("/dev/adc0", &adc_dev)

应用层:
  fd = open("/dev/adc0", O_RDONLY)
  read(fd, &adc_msg, sizeof(adc_msg))
  → 返回多通道采样值

DMA 模式:
  定时器触发 → ADC 扫描 → DMA 传输
    → 环形缓冲区 → 应用读取
```

### 数据流

```
单通道查询:
  应用 → read()
    → ADC 软件触发
    → SAR 转换 → DR 寄存器
    → 返回 12-bit 值

多通道 DMA:
  TIM 触发 → ADC 扫描 CH0-CHn
    → DMA → 内存环形缓冲区
    → 中断通知 → 应用 read()

## 理由

选内部 VREFINT 通道使真机 drivertest 无需任何外部布线即可跑，且其
±2 LSB 转换抖动天然满足 drivertest_adc 的 "两次读数须变化" 判据
（-d 1：需 delta≥2），而冻结的桩值 delta=0 永远无法通过 —— 保证测试
诚实反映真实硬件转换。

补齐扫描/DMA/AWD 时同样选片内电压（VBAT + VDDCORE）而非外部输入：
真机大赛板无已知外部模拟布线，片内通道让三条能力都能在任意板上直接
MEASURED。新设备 `/dev/adc1` 与 `/dev/adc0` 完全隔离（独立实例 + 独立
Kconfig 门控），使既有 drivertest_adc 零回归；DMA 复用共享 GPDMA 驱动
而非另起炉灶，符合 ADR-011 "单一 GPDMA 驱动服务所有外设" 的架构。
